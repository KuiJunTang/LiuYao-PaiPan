# 六爻排盘 · 规则口径

## 一、历法

| 项 | 口径 | 依据 |
| --- | --- | --- |
| 时区 | 北京时间（UTC+8），不做夏令时还原 | 通例 |
| 年柱 | 立春换年 | 干支柱以节气为准，非正月初一 |
| 月柱 | 十二「节」换月：立春→寅、惊蛰→卯、清明→辰、立夏→巳、芒种→午、小暑→未、立秋→申、白露→酉、寒露→戌、立冬→亥、大雪→子、小寒→丑 | 月建取节不取中气 |
| 日柱 | 连续六十甲子；23:00 起归次日（晚子时） | 主流排盘口径，可关 |
| 时柱 | 五鼠遁：甲己起甲子、乙庚起丙子、丙辛起戊子、丁壬起庚子、戊癸起壬子 | 子时 23:00–00:59 |
| 旬空 | 日柱所在旬之旬首后二支 | 六十甲子分六旬，每旬十干配十支，余二支为空 |

**日柱与时柱一律自算**：日柱用儒略日＋六十甲子平移（`tables_js.DAY0_JS`），时柱用五鼠遁。曾有旧 bug：
直接调天文库的 `getShiGz`，该函数在 23 时自行换日干，与本模块晚子时处理重复，致 23 时后时柱错一位
（已修，见 selfcheck「历法·时柱五鼠遁」）。

**历法数据从哪来**：节令、农历、日柱基准三张表由 `build_tables.py` 用寿星天文历（sxtwl）一次算出，
存进 `scripts/tables_js.py` 随包分发；运行期只读表，**不需要 sxtwl 或任何天文库**（1.5.0 起）。
故 Windows 上不必为 C++ 扩展准备编译环境。表值由开发期 `check_tables.py` 重算比对把关；
干支组合、换年换月、旬空、农历换算等逻辑另由 `audit_gua.py` 独立复核。分工是：**表归天文库校，逻辑归公式校**。

**可排年份：1900–2100**。历法表（`build_tables.py` 的 `YEAR_FROM..YEAR_TO`）、页面年份下拉
（`engine_js.py` 的 `years()`）、Python 端护栏（`lifa.YEAR_MIN/YEAR_MAX`）三处同此一界，不得各自为政。
越界即**明确报错**，不静默降级：1899 年旧版抛裸 `KeyError`，2101 年旧版 Python 能算而浏览器表已止于 2100，
同一份 HTML 静态首屏与交互后差一年（BUG-50）。

**农历不存在的日期一律报错，不替用户改日子**（BUG-49）：

| 情形 | 处理 |
| --- | --- |
| 小月（29 天）选「三十」 | 报「农历 2025 年闰六月只有29天，没有三十」；日期下拉本身只列到廿九 |
| 所在年无此闰月 | 报「农历 2025 年没有闰八月（该年闰六月）」；前端月份列表随年重建，换年后无此闰月即落回本月同号 |
| 公历 2 月 30 日一类 | 日期下拉按大小月与闰年收口，根本选不出 |

校验方式：`lunar_to_solar()` 先按表核定该月月长与闰月是否存在，越界即报错（不再依赖天文库的默认行为——
旧版天文库对越界日是静默顺延的）；前端 `lunarToSolar()` 遇越界日一律落**本月底**，绝不跨月。

## 五、六亲

以**卦宫五行**为「我」，对本爻地支五行定：同我兄弟、生我父母、我生子孙、克我官鬼、我克妻财。

**变卦六亲仍以本卦卦宫为准**，不以变卦自身宫论。例：天地否（乾宫金）之雷风恒，
恒虽属震木，其六亲仍依乾金推——六爻戌土为父母、申金为兄弟、亥水为子孙，与参考图一致。
此为主流六爻口径：变爻只论动变，宫位不变。

## 六附 · 起卦概率（依《周易六爻概率学解密》）

> 置于「六神」之后、「伏神」之前。原编号标作「七之前」，为免牵动后文编号而沿用其序，
> 今统一称「六附」，表示本章是六神之后的补充，不参与主序号。

出处：复城道长公众号 2024-07-23《周易六爻概率学解密》
（https://mp.weixin.qq.com/s/3YP9Gpa3Ds3vyqU1FX0vgQ）。

**三枚钱法，反（背）为阳**。每一次摇钱有八种等概情形：

| 背数 | 情形 | 爻 | 概率 |
| --- | --- | --- | --- |
| 0 | 正正正 | 老阴 6（动） | 1/8 |
| 1 | 正反正／正正反／反正正 | 少阳 7（静） | 3/8 |
| 2 | 正反反／反反正／反正反 | 少阴 8（静） | 3/8 |
| 3 | 反反反 | 老阳 9（动） | 1/8 |

故每爻：动 1/4、静 3/4；阳（不论动变）1/2、阴 1/2。由此一次起卦的动爻个数：

| 动爻数 | 概率 |
| --- | --- |
| 0（静卦） | 17.80% |
| 1 | 35.60% |
| 2 | 29.66% |
| 3 | 13.18% |
| 4 | 3.30% |
| 5 | 0.44% |
| 6 | 0.024% |

**实现须逐枚掷钱**：`secrets.randbelow(2)`／`crypto.getRandomValues` 取背字，三枚累加成背数，
再按 `{0:6, 1:7, 2:8, 3:9}` 取爻。**不得**用 `choice((6,7,8,9))` 或 `rnd()*4` 取整——
那是均匀分布，老阴老阳各占 1/4，与摇卦不合（BUG-22）。

守护分两层，缺一不可：

- **理论自校**（7 条）：`概率·背数取爻`、`概率·爻值权重`、`概率·动爻七档合文`、
  `概率·合计为一`、`概率·静卦 17.80%`、`概率·一动 35.60%`、`概率·六动万分之二`
  —— 验「二项式展开」与上文七档表相符。
- **实现结构**（4 条）：`起卦·逐枚掷钱（Python 三次取背）`、`起卦·不得按权重直抽爻值（Python）`、
  `起卦·逐枚掷钱（浏览器 flip×3）`、`起卦·不得按权重直抽爻值（浏览器）`
  —— 验源码写法确为三枚相加，**不是**按 1/8·3/8·3/8·1/8 的权重直抽爻值。
- **实现分布**（3 条＋审计）：`起卦·掷钱概率`、`起卦·动爻两成半`、`起卦·非均匀`；
  `check_toss.py` 另有卡方检验（df=3，阈 16.27）与「自动＝手动同值同盘」40 轮。

> 为何两层都要：分布对**不等于**机制对。若改成按权重直抽，分布、动爻率、卡方**全都照样通过**，
> 却已不是摇六次三钱、也无从核背数——故必须有结构断言盯住写法（指令 86）。

## 十、输出与可复制

盘面既要在屏上好看，也要能被带走（道长指令 04）。两条硬规矩：

1. **爻线只用字符**，不用 CSS 色块、不用图片、不用 SVG。
   阳爻 `───`（U+2500 盒线字 ×3）、阴爻 `─　─`（U+2500＋全角空格＋U+2500）：
   盒线字形居字格中位，三块可拼成一线，阴阳各三字宽，故起止对齐。
   早先用 U+2581（下八分之一块）绘制，其墨迹贴字身底，粘进 Word 后整条爻线沉底、
   与六亲字上下不居中（指令 78），故弃；亦曾试 U+2501 `━`，自带左右边距三块连不成线，故弃。
   （爻线内那个全角空格是用来撑开阴阳爻位差的，格内 `nowrap`、恒三字宽，不涉行尾裁切；
   与下文「神煞禁全角空格」并不冲突。）
2. **盘面只用真 `<table>`**，一行九格，表头 `colspan` 6＋3。
   grid／flex 排版在浏览器里再整齐，粘进 Word 也只会按段落流重排，列必散。
3. **列宽写明**：动卦表宽 550px（A4 正文宽约 602px 以内）、静卦 318px，列宽用 `<colgroup>` 百分比，
   间隙并入列宽而非 `padding`。间隙若只靠 padding，Word 压缩列宽时内容随即崩开折行。
4. **神煞用真空格**：各项以**半角空格**分隔（行尾可裁），再用 `word-spacing:.4em` 补视觉间隙。
   **不可用全角空格 U+3000**——它在 `white-space:normal` 下行尾不被裁，长行换行处会残留约 13px
   把该行撑宽，窄屏 358–376、415–430px 即溢出右缘（BUG-45）。

窄屏一律不折行：字号按 `calc((100vw - 26px)/n)` 等比缩字（页头与面板 n=32、盘面 n=36.667、
静卦页 n=21.2，上限 15px），整表缩进一屏，六亲不拆成两行。

## 十一、版式与面板口径

1. **卦名居中**：卦名用 `colspan` 跨组，居中于列组。要让「看起来居中」，须令每组首尾列留白相等，
   故列宽按此调：本卦取 c1–c6（5.818／14.091／14.364／9.091／5.455／12.318%），
   变卦取 c7–c9（17.773／12.727／8.364%）。禁用 `padding` 硬推——字宽随字体变，padding 是死的。
   偏差由 `check_center.py`（阈 3px，72 页全扫）与 `check_layout.py`（阈 6px）两处断。
2. **静卦独宽**：静卦无动爻，末列必空，若仍用九列比例会把卦体推偏。故 `.board.six` 另设表宽
   318px 与专属比例（c1–c6：10.063／24.371／24.843／15.723／12.579／12.421%）。
3. **页脚**：logo 内联为 data URI（单文件、零外链），外链官网、带 `alt`；落款两行，
   第一行为「署名 · 魁君堂官网：URL」，第二行为「微信公众号／微信」。桌面端（容器 ≥600px）
   信息行收纳为**一行居中**，窄屏仍折行以免字过小（指令 82）。
4. **面板**：卡片＋四组（信息／方式／时间／六爻），组名左列、控件右列；组名加粗并前置朱条。
   组高一律 `min-height:30px`、组距 13px——只调 `margin` 不管组高，视觉段距仍不等。
   时间组顺序：年月日时＋分，末接「现时」。六爻**恒两行三列**（`repeat(3,minmax(0,1fr))`），
   任何宽度都不降列（BUG-30）。
   窄屏组名转为上方小标题；时间组 `.date{display:contents}` 并入单行网格。
5. **折叠**：`#panel[hidden]` 即收起；按钮在**页顶右上角**，文案与 `aria-expanded` 同变；
   同时给 `.pan` 加 `.collapsed`，折叠条换成带上边线的工具栏。
6. **复制与打印**：信息区右上「复制卦例」钮（复用 `.fold`、去箭头），点按以 `Range` 选中
   head＋board 后 `execCommand('copy')`，失败回退纯文本；钮置于 `#pan-head` **之前**，
   故不在选区、全选亦不含其文字。`@media print` 隐藏两枚操作钮并收回首行让位内距（BUG-47）。

## 十二、双引擎同源

**首屏**盘面由 Python（`render.py`）生成静态 HTML；此后任何交互（改爻、改时、掷钱、切历法）
由页面内 JS 引擎（`engine_js.py`）重排。两者必须逐字同源，其数据表（节令、农历、卦理、神煞）
由 `build_tables.py` 从 Python 侧生成（`tables_js.py`），不手写、不手改。
`parity_check.py` 用无头浏览器跑 JS，取 head 与 board 的 HTML，去掉标签间空白后与 Python
逐字比对；不一致即视为缺陷。**改任一侧必两侧同改**，只改 Python 侧会在交互后回退旧观感（BUG-38）。
比对现为 **39 组**（含闰月、晚子时关闭、1900/2100 两端年份、公历闰日四类边界），
另加**农历全量**：1900–2100 每年每月（含闰月）共 2486 个月的月长与月首／月末换算穷举。

**初始态亦须同源**（BUG-51）：页面 `window.__INIT__` 必须承载起卦时的 `cal`、`leap`、`lateZi` 三项，
否则走的是「另一套口径」——农历闰月页会按公历填月份下拉，读出 `NaN` 月序，打开即错日；
`--no-late-zi` 起的卦，一动控件日柱就换。改 `render._init_js()` 时这三项不可漏。

卦类括注（指令 05、20、21）：六合、六冲、游魂、归魂四类，凡属之必标于卦名后；
八纯**不标**（八纯卦必为六冲，括注中仍见「六冲」）；
本卦变卦皆然。类别的判定见第八节。
